# Анализ legacy_calc.py

## Логика алгоритма

Функция `calc_bonus(x, y, z)` рассчитывает бонус в зависимости от суммы
продаж (`x`), количества месяцев (`y`) и категории клиента (`z`):

- если сумма продаж `x > 1000`, то за каждый из `y` месяцев начисляется
  процент от суммы продаж в зависимости от категории клиента:
  15 % для `z == 1`, 10 % для `z == 2`, 5 % для остальных категорий;
- иначе бонус считается сразу от `x * y`: 2 % при `y > 10`, 1 % — в
  остальных случаях.

## Выявленные недостатки (Code Smells)

1. Магические числа: 1000, 0.15, 0.10, 0.05, 10, 0.02, 0.01. Их нужно вынести
   в константы.
2. Плохой нейминг: `x`, `y`, `z`, `res` не отражают бизнес-смысл
   (`sales_amount`, `months`, `client_category`, `bonus`).
3. Глубокая вложенность: цикл внутри условия внутри условия.
4. Лишний цикл: в ветке `x > 1000` каждый проход прибавляет одно и то же
   значение, поэтому цикл эквивалентен умножению на `y`
   (`res = x * y * rate`).
5. Неиспользуемая переменная цикла `i`.
6. Нет валидации входных данных: отрицательные `x`/`y` или неизвестная
   категория `z` молча дают некорректный результат.
7. Несогласованность веток: в первой ветке `res` накапливается (`+=`), во
   второй — перезаписывается (`=`).
