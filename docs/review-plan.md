## 2. Цели ревью

1. Обеспечить производительность: каждый отчётный запрос на объёме в
   миллионы строк выполняется не дольше 5 секунд.
2. Гарантировать корректность данных: суммы, остатки и прогнозы в отчётах
   совпадают с эталонными значениями, ошибки агрегации исключены.
3. Обеспечить читаемость и сопровождаемость SQL-кода, чтобы модуль могли
   поддерживать другие разработчики.

## 3. Критерии проверки (чек-лист)

### 3.1. Функциональная корректность

- [ ] Результаты каждого отчёта на контрольном наборе данных совпадают с
      эталоном на 100 % (сверка итоговых сумм и количества строк).
- [ ] Все `JOIN` имеют явные условия соединения; нет «размножения» строк —
      `COUNT(*)` до и после соединения проверен для каждой связи 1:N.
- [ ] Обработка `NULL` явная (`COALESCE`, `IS NULL`): 0 мест, где `NULL`
      искажает `SUM`/`AVG` или условие `WHERE`.
- [ ] Границы периодов отчёта заданы полуинтервалом `[начало; конец)`,
      проверены на данных за последний день месяца.

### 3.2. Безопасность / Надежность

- [ ] 0 запросов с конкатенацией пользовательского ввода — только
      параметризованные запросы (защита от SQL-инъекций).
- [ ] Учётная запись отчётов имеет права только `SELECT` на нужные схемы.
- [ ] Каждый запрос имеет `statement_timeout` не более 5 секунд.

### 3.3. Производительность

- [ ] Время выполнения каждого запроса на копии продовой БД (≥ 10 млн строк)
      ≤ 5 секунд (замер `EXPLAIN (ANALYZE, BUFFERS)`, 3 прогона).
- [ ] В планах выполнения нет `Seq Scan` по таблицам больше 1 млн строк без
      обоснования; для фильтров и соединений есть индексы.
- [ ] Нет коррелированных подзапросов в `SELECT`-списке по большим
      таблицам; 0 использований `SELECT *`.

### 3.4. Читаемость и стиль

- [ ] Ключевые слова SQL в верхнем регистре, отступ 4 пробела (согласно
      `.editorconfig`), одна колонка на строку в `SELECT`.
- [ ] Сложные запросы разбиты на CTE (`WITH`) с осмысленными именами; у
      каждого запроса есть комментарий с назначением отчёта.
- [ ] Алиасы таблиц осмысленные (`s` — sales, `p` — products), не `a`, `b`, `c`.
