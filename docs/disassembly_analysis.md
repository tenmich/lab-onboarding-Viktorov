# Анализ ассемблерного фрагмента (x86-64, синтаксис AT&T)

## Исходный фрагмент

```asm
    movl $0, -4(%rbp)
    movl $1, -8(%rbp)
    jmp .L2
.L3:
    movl -8(%rbp), %eax
    addl %eax, -4(%rbp)
    addl $1, -8(%rbp)
.L2:
    cmpl $10, -8(%rbp)
    jle .L3
    movl -4(%rbp), %eax
```

## Роли ячеек памяти и регистров

| Место          | Роль                         | Начальное значение |
|----------------|------------------------------|--------------------|
| `-4(%rbp)`     | аккумулятор `sum`            | 0                  |
| `-8(%rbp)`     | счётчик цикла `i`            | 1                  |
| `%eax`         | временный регистр / результат функции | —         |

## Логика работы

1. Локальные переменные на стеке инициализируются: `sum = 0`, `i = 1`.
2. `jmp .L2` сразу переходит к проверке условия — это типичная для
   компилятора GCC компоновка цикла `for`/`while` (проверка внизу).
3. `cmpl $10, -8(%rbp)` + `jle .L3`: пока `i <= 10`, выполняется тело.
4. Тело `.L3`: значение `i` загружается в `%eax` и прибавляется к `sum`,
   затем `i` увеличивается на 1.
5. После выхода из цикла `sum` копируется в `%eax` — по соглашению System V
   AMD64 ABI в `%eax` возвращается результат функции.

Итог: функция вычисляет сумму целых чисел от 1 до 10, то есть **55**.

## Эквивалентный код на C

```c
int sum_1_to_10(void)
{
    int sum = 0;
    for (int i = 1; i <= 10; i++) {
        sum += i;
    }
    return sum;
}
```

## Эквивалентный код на Python

```python
def sum_1_to_10():
    total = 0
    i = 1
    while i <= 10:
        total += i
        i += 1
    return total
```
